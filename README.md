# Guardian Landing Page

This repository contains the source for the Guardian landing page, a small React application built with [Vite](https://vitejs.dev/).

It was created from the standard React + Vite template and then customized for the project. The goal is a simple, static, client‑side landing page composed of several React components.

---

## 📦 Technologies & Languages

- **React** (via `<script type="module">` entry) with **JSX** syntax
- **JavaScript** for logic and data (`.js`, `.jsx` files)
- **CSS** for styling (`.css` files in `src/` and `index.css`)
- **HTML** for the single-page shell (`index.html`)
- **JSON** used in configuration (`package.json`, `package-lock.json`) and data definitions

All dependencies are managed with npm. Run `npm install` to set up.

---

## 🧱 Project structure

```
/public             # static assets (images, favicon)
/src
  main.jsx          # application entry point
  index.css         # global styles
  data.js           # shared content used by multiple sections
  components/       # React section components
    HeroSection.jsx
    CapabilitiesSection.jsx
    BuiltForEveryoneSection.jsx
    WhyGuardianMattersSection.jsx
    KeepingGuardianFreeSection.jsx
    TeamSection.jsx
    Footer.jsx
    SectionHeading.jsx  # reusable heading element
```

### 🧩 Landing page sections

1. **Hero** – introduction banner
2. **Capabilities** – what Guardian can do
3. **Built‑for‑Everyone** – three user audiences / pillars
4. **Why Guardian Matters** – value proposition
5. **Keeping Guardian Free** – cost/mission statement
6. **Team** – list of project contributors
7. **Footer** – links/credits

The components are mostly presentational; any shared textual data lives in `src/data.js`.

---

## 🎨 Styling & variables

- Global CSS is in `src/index.css`; component-specific styles are imported from their `.jsx` files.
- There are no CSS preprocessors or CSS-in-JS libraries in use.
- No environment variables are needed for this static site. If you add any (`.env` files), update `.gitignore` accordingly.

## 🚀 Getting started (for collaborators)

1. `git clone <repo-url>`
2. `cd landing-page` (or the repository folder name)
3. `npm install` – installs dependencies; required before running anything.
4. `npm run dev` to start the development server (hot reload on save).
5. `npm run build` to create `dist` for production builds.

> **Before you start contributing:**
>
> - Pull the latest changes from `main` and create a feature branch:
>   ```bash
>   git checkout main
>   git pull
>   git checkout -b feature/your-description
>   ```
> - Run `npm run lint` and fix any lint errors before committing. The repo uses ESLint for consistent style.
> - Keep components small and share common text in `src/data.js` to avoid duplication.
> - Document any new dependencies or tooling you add.
> - If you add environment variables or new generated files, update `.gitignore` accordingly.

Lint with `npm run lint` before pushing to keep code style consistent.
